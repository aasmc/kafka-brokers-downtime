# Эксперименты с отказом брокеров Kafka

Проверено поведение партиции, продюсера и консюмера при внезапном отказе трёх из шести брокеров.

## Условия

| Параметр | Значение |
|---|---|
| Стенд | Kafka 3.9.0, ZooKeeper 3.8.4, 6 брокеров |
| Топик | `downtime-experiment`, 1 партиция, `min.insync.replicas=2` |
| Отказ | `docker kill kafka-1 kafka-2 kafka-3`, outage около 50 с, затем перезапуск |
| Нагрузка | 1 сообщение/с, `delivery.timeout.ms=10000` |
| Варианты | `unclean.leader.election.enable=false/true`; RF=3 или 4; `acks=all` или 1 |
| Идемпотентность | Включена при `acks=all`, отключена при `acks=1` |

ISR — набор синхронизированных реплик партиции.

## Результаты

| RF, `acks`, replicas | `unclean` | Партиция во время outage | Запись и чтение | ACK / ошибки / прочитано* |
|---|---|---|---|---:|
| 3, `all`, `[1,2,3]` | `false` | `Leader: none`, `Isr: 3` | Новые записи и чтение остановлены | 47 / 44 / 47 |
| 3, `all`, `[1,2,3]` | `true` | `Leader: none`, `Isr: 3` | Новые записи и чтение остановлены | 36 / 54 / 36 |
| 4, `all`, `[1,2,3,4]` | `false` | `Leader: 4`, `Isr: 4` | Запись заблокирована при ISR < 2; новых сообщений нет | 41 / 60 / 41 |
| 4, `all`, `[1,2,3,4]` | `true` | `Leader: 4`, `Isr: 4` | Запись заблокирована при ISR < 2; новых сообщений нет | 47 / 53 / 47 |
| 4, `1`, `[1,2,3,4]` | `false` | `Leader: 4`, `Isr: 4` | После выбора лидера запись возобновилась; чтение — после восстановления ISR | 79 / 22 / 79 |
| 4, `1`, `[1,2,3,4]` | `true` | `Leader: 4`, `Isr: 4` | После выбора лидера запись возобновилась; чтение — после восстановления ISR | 58 / 33 / 58 |

\* Счётчики за весь прогон: `PRODUCER_ACK` / `PRODUCER_ERROR` / `CONSUMER_RECORD`.

## Выводы

| Наблюдение | Вывод |
|---|---|
| Нет живых назначенных реплик | Партиция становится offline независимо от `unclean.leader.election.enable`. |
| Живая ISR-реплика на брокере 4 | Выполняется clean election, лидером становится брокер 4; unclean-флаг не влияет на результат. |
| Назначение реплик во всех прогонах | Автоматического переноса на брокеры 5–6 нет: выбор лидера не является переназначением реплик. |
| RF=4, `acks=all`, `Isr: 4` | `min.insync.replicas=2` блокирует запись несмотря на наличие лидера. |
| RF=4, `acks=1`, `Isr: 4` | Лидер подтверждает записи, но high watermark не растёт при ISR < 2, поэтому консюмер видит их только после восстановления ISR. |
| Возврат брокеров 1–3 | Запись и чтение восстанавливаются автоматически; в этих прогонах дублей не обнаружено, все ACK-сообщения прочитаны. |

Результаты по целостности относятся к выполненным прогонам и не являются общей гарантией сохранности при `acks=1` или unclean election.
